## 6. FINAL ARCHITECTURE DECISION (where we landed)

What Flavio described = an Anthropic **Managed Agent (CMA)**. Anthropic runs the
agent loop AND hosts a container that can **mount the GitHub repo**. The agent reads
CLAUDE.md + profiles + past outreach, drafts using the real playbook, and can
`git commit + push` the new file (= "submit"). No VPS to self-host. Anthropic hosts
the compute.

Flavio only builds the **Telegram bridge**, and that can live in **n8n** (already
runs it) — unifies with the Apify finder in one n8n instance.

### The flow
```
Flavio texts Telegram bot ("draft this <job link>")
  -> n8n Telegram Trigger (the bridge — only part to build)
  -> Anthropic Managed Agents API: create/continue session
       - GitHub repo mounted at /workspace/personal-upwork
       - reads CLAUDE.md + profiles + outreach history (full playbook context)
       - writes outreach/<slug>.md using 5-slot rules
       - git commit + push   <- "submit"
  -> streams draft back -> n8n -> Telegram reply
  -> Flavio edits on phone -> pastes into Upwork
```

### Created ONCE, reused:
- An **Agent** config: model `claude-opus-4-8` + system prompt pointing it at the
  playbook in the repo. Store the returned `agent_id`. (Agent is versioned; update
  it, don't recreate per run.)
- A **GitHub fine-grained PAT**, scoped to just this repo, `Contents: Read and write`.

### Per message: create/continue a **session** referencing agent_id + mount repo
via a `github_repository` resource (url + PAT + mount_path).

### Key grounded facts (from claude-api skill, verified today):
- Managed Agents is beta; SDK auto-sends header `managed-agents-2026-04-01`.
- Flow is mandatory: Agent (once) -> Session (every run). model/system/tools live
  on the AGENT, never the session. Session takes only `agent` (id) + `environment_id`.
- `github_repository` resource = filesystem + git (clone/edit/commit/push via git
  proxy that injects the PAT outside the container — code in the container can't read
  the token). To open PRs you'd ALSO need the GitHub MCP server; for our use,
  push-to-branch or push-to-main is enough, no PR needed.
- Events: open the stream BEFORE sending the kickoff message; break on
  status_idle with a terminal stop_reason (not requires_action) or status_terminated.
- Cost: Apify ~$0.05/trigger + Claude tokens per draft (cents). Idle = free.
